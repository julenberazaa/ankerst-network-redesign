# Ankerst UI reference — state after Run 7

Captured on 2026-08-24 from commit `6ec846e`, before Run 8. This folder is a
visual handoff for parallel UI work: it records what exists and how the main
flows behave; it is not a statement that every current design decision should
be preserved.

Desktop captures use a 1440 × 1000 viewport. Mobile captures use 390 × 844.
All names, companies, opportunities, prices and contact details are synthetic.
No AI/API key was used. Full-page images may be tall because they deliberately
show the complete form or comparison surface.

## Product boundary

- **Canonical MVP:** Network profile, Opportunities, Private invitations,
  Proposal Studio, exact-revision comparison/export, Team and Pilot operations.
  These are the priority for the parallel redesign.
- **Legacy / transitional:** public automation intake, legacy company-profile
  onboarding, legacy leads inbox and legacy AI proposal intake. Keep them
  recognizable when assessing navigation, but do not treat them as the target
  architecture or create a second proposal flow around them.
- The demonstrated scenario is one Spanish buyer scope from **Norte
  Components**, two invited providers (**Axiom Robotics** and **Basque
  Controls**), two immutable responses and one shortlisted response. Axiom also
  has a finalized standalone proposal, proving that Studio works without a
  buyer on Ankerst.

## Flow represented by the populated screens

1. A buyer creates a private opportunity, completes the scope and publishes an
   immutable revision.
2. Deterministic matching ranks only approved providers with complete, current
   profiles; the buyer manually chooses whom to invite.
3. Each provider reviews the exact disclosed revision and may open a private
   draft in the shared Proposal Studio.
4. A provider completes assumptions, exclusions, dependencies, risks,
   delivery and commercial fields, confirms uncertainties and submits an
   immutable revision.
5. The buyer compares responses tied to the same opportunity revision and
   records an explicit shortlist/accept/reject/revision request before any
   eventual award.
6. A provider can independently use the same Studio to finalize and export a
   proposal even when no buyer account or Network invitation exists.

## Redesign cautions

- Do not make draft provider content visible to buyers or suggest that
  matching, invitation, submission or award is automatic.
- Keep unknowns visible as assumptions, exclusions, dependencies, risks or
  questions; Run 8 will add evidence and adaptive clarification on this model.
- Preserve exact revision identity, human confirmation and commercial-state
  history even if the information hierarchy and interaction design change.
- The current interface language is English while proposal/scope content may
  be Spanish or English. Full UI localization is not complete yet.
